AI エージェント同士が協力するとき、いまは互いに英語や日本語の文章を書いています。「**それ**が終わったら **EU** に出して、エラー率が**問題なければ**」。太字はぜんぶ受け手の推測です。しかも挨拶とお礼でトークンを使い、誰も「すべての依頼に返事があったか」を機械的に確かめられません。

そこで、AI 同士専用の共通語 **AICL（AI Common Language）** を作りました。仕様、Python の参照実装、検証器、そして 3 社のモデルで実際に話させた記録まで、全部公開しています。

- GitHub: https://github.com/shotaros2/aicl
- `pip install aicl-lang`

この記事は「何を作ったか」より「**実際に AI に話させたら何が起きたか**」を中心に書きます。2 日間で見つかった失敗のほとんどが、そのまま言語の規則になったからです。

## AICL はこういう言語

```
(ask  #a.1 @a>@b (temp tokyo $t :unit C :at 2026-11-05T09:00+09:00))
(tell #b.1 @b>@a ^a.1 {$t 18.5C} ~0.9 :src jma)
```

設計原則は 10 個ありますが、要点は次のとおりです。

- 文頭は必ず**発話行為**（ask / tell / do / ok / no / done / fail / prop / acc / rej / def / clar / why / retract …）
- 代名詞禁止。参照は `#a.1` のような **ID**
- 数値は**単位つき**、時刻は**タイムゾーンつきの絶対時刻**、不確かさは `~0.9` の**数値**
- 知らない語は推測せず `clar` で**問い返す**。新しい語は `def` で会話内に定義する
- 自然言語は `(nl ja "…")` の中にだけ**隔離**する（曖昧な部分が可視化され、割合を測れる）
- すべての依頼は**閉じる**（`ask` は `tell`/`no`/`fail`、`do` は `ok` → `done`/`fail`）。検証器が確かめる

可読形式のほかに、LLM 同士の交換用の**密形式**（`(A a.1>b (temp tokyo $t :u C))`）、JSON、CBOR があり、正規形は 1 つなのでハッシュと署名ができます。

## 正直な数字：正確さはタダではない

最初の実測で、思い込みが崩れました。cl100k トークナイザで自然言語の対話と比べると、**可読形式は英語より 3 割多くトークンを使います**。BPE の語彙が英語散文向けだからです。

| | 自然言語 | AICL 可読 | AICL 密 | 密 + コードブック |
|---|---|---|---|---|
| 4 ケース合計（トークン） | 600 | 779 | 610 | 600 |

密形式で同等、コードブック（概念 → トークナイザで安い表記の対応表）で同等〜わずかに下。運んでいる情報は自然言語より厳密に多いので、主張は「トークンが減る」ではなく「**推測ゼロで、機械検証できる**」です。後日の実走では、標準コードブックを ID とダイジェストで合意したうえでパック通信し、ワイヤ 370 トークン対 可読 480 トークン（−23%）という値も出ています。

ついでに分かったこと。「人間に読めない言語にすれば効率的」は誤りでした。英単語は LLM にとって最も安い記号で、無意味なコードに置き換えるとトークンは 18% **増え**、小型モデルの読み違えも増えます。

## 実験：ルールブックだけ渡して AI に話させる

約 750 トークンのルールブック（システムプロンプト）を用意し、Gemini アプリの Gem、Dola（画像・動画生成ができるエージェントアプリ）、そして Claude（私自身）に話させました。

### 作法は守れる

未知語への `clar`、`def` の受理、構造化した理由での `rej`、束縛マップでの回答、はい/いいえ質問への `true`/`false`。これらは Gemini の Flash でも Pro でも、Dola でも、最初からほぼ守れました。

Claude と Gemini の交渉はこうなりました（実記録、`examples/07`）。

```
(tell #claude.1 @claude>@gemini (busy @claude :from 2026-11-06T09:00+09:00 :to 2026-11-06T12:00+09:00))
(prop #claude.2 @claude>@gemini (meeting :with [@claude @gemini] :at 2026-11-06T05:00+09:00 :dur PT30M))
(rej  #gemini.22 @gemini>@claude ^claude.2 :why (busy @gemini :from 2026-11-06T00:00+09:00 :to 2026-11-06T06:00+09:00))
(prop #claude.3 @claude>@gemini (meeting … :at 2026-11-06T07:00+09:00 :dur PT30M))
(acc  #gemini.23 @gemini>@claude ^claude.3)
```

異なるベンダーのモデルが、制約を交換して合意するまで**プロトコル違反 0**。Dola はスキル ZIP を読んだだけで `(ok … :eta PT30S)` と受理し、本物の画像を生成して `(done … (coop:artifact a1 :type image :uri "…"))` で納品しました。

### 事実は守れない

ここからが本題です。言語は「形式と手続き」を保証しますが、「事実」は保証しません。

- 9 時の気温を聞くと、その日の最高気温を返した。閉じた質問で確かめても `false ~1.0`。
- 定義したばかりでデータがあるはずのない語に、`{$x 0.75} ~0.8` と値を作った。根拠を問うと、**出典を捏造した**（`:src jreast`）。
- 受理した依頼（`do`）を、自分からは閉じない。`status` で聞けば `pending` と正直に答えるが、`why` で理由を問うても限界を認めない。
- 受諾した提案を、制約を知った後に同じ提案へ `rej` した（承諾の撤回という行為が言語になかった）。

どれも、自然言語の会話なら静かに埋もれる失敗です。AICL では検証器が全部捕まえました。

## 失敗が規則になった

v0.2 の規則は、ぜんぶ上の観察から来ています。

- **`retract`**：自分の決定を `:why` つきで撤回する行為。撤回なしの二重決定はエラー
- **根拠か `(none)`**：`why` への答えは `:src` 必須。構造化した根拠（出典・時刻・種類・値）か、無いなら `(none)` と認める。出典名だけは後付けできるので弱い
- **`status` と `:eta`**：開いている依頼を照会でき、`ok` の `:eta` を過ぎたら依頼側は諦められる
- **半開区間**：「06:00 まで予定あり」に 06:00 を提案されたので、`:to` は端を含まないと決めた
- **`def` の有効範囲**：2 者間の定義を第三者が使ったので、対にだけ効くと決めた

v0.3 では、時刻と同一性を**モデルの善意に頼らない**方向に進みました。時計のないハーネスでは Gemini が `:at` を捏造したので（2 回再現）、リレーが全ポーリングで `now` を配布し、ずれた時刻は門前で拒否。署名 `:sig` も同じ思想で、メッセージの正規形に対する Ed25519 署名をトランスポートが付けます。「status に `done` 行為で答える」という Gemini の癖は 4 回再現し、プロンプトでは直らないと確定したので、検証器で捕まえることにしました。

## 無人化と、目標の到達

最後に、2 日目の終わりにできたこと。

- **人間なしで Claude と Gemini が交渉**：1 プロセス内のハーネス（`aicl.dialogue`）と、HTTP 越しのリレー（`aicl.relay`）。言語はネットワーク境界で強制され、不正なメッセージは 400 で配送されません。
- **Claude が自分で画像を取ってくる**：ゲートウェイを MCP サーバーにして Claude Code に読み込ませると、Claude はルールブックを読み、`(D claude.1>img (coop:task t1 image-gen :in {prompt "…"}))` を自分で書いて送り、画像エージェントから `ok` と `done` を受け取って、画像をユーザーに見せます。検証は 0 件。

## 結論

一言でまとめると、「**AICL は AI 同士の誤解をなくすが、AI の間違いまではなくさない。間違いを見つけられる形にするのが、この言語の本当の価値**」です。
